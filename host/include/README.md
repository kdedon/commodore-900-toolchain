# Vendored Coherent headers

The host cross-build compiles Coherent K&R sources with gcc, and those sources
include headers the host does not have.  They are vendored here, so building the
compiler needs no OS tree beside it.

| header | consumer | why |
|---|---|---|
| `path.h`, `access.h` | `src/cc` (cc0.c, cc.c) | the driver's path/exec-search declarations |
| `n.out.h`, `l.out.h` | `src/as`, `src/ld` | the object and executable file formats |
| `mtype.h` | `src/as`, `src/ld` | machine-type constants (`M_Z8001`) |
| `canon.h` | `src/as`, `src/ld` | PDP-canonical field conversion |
| `ar.h`, `sys/dir.h` | `src/ld` | archive member layout; `ar.h` includes `sys/dir.h` |

These are COHERENT 3.2 headers, copied verbatim.  Nothing here is a shim: the
host-only edits (exact-width packed structs, the `types.h` substitute, the host
`sys/stat.h`) are still generated by the build scripts, because they are host
workarounds and must not look like the native truth.

**Drift.** `n.out.h`, `l.out.h`, `mtype.h`, `canon.h` and `ar.h` describe the
object format, which is a contract BETWEEN this toolchain and the OS.  If the OS
tree's copies ever change, these must change with them or the linker will write
files the kernel cannot exec.  The format has not moved since the Z8001 branches
were settled, and the toolchain is the side that defines it, so the copy lives
here and the OS follows.
